A model can claim it wrote the file, moved the event, or read the document, and a thin wrapper will print that claim as fact. Ghost is built the other way around: every capability is a function the app owns, the app checks permissions and path boundaries before it runs, and what returns to the model is the actual result, including the failure.

Capability harness

  • A local intent classifier runs first, with no network call, and selects one of fourteen intents. That choice determines the route: a local model in LM Studio or Ollama, a hosted API, or the user's own Claude Code or Codex subscription.
  • The tool schema is assembled from the permissions that are actually enabled, so a disabled capability is invisible to the model rather than discouraged. Execution re-checks the same policy.
  • Tools carry three risk tiers. Destructive ones always require confirmation, and the confirmation dialog receives the real argument JSON rather than the model's description of it. Unknown tool names fail closed.
  • Local models are probed on first launch for tool-calling support and assigned the safest calling convention they can handle, so models without native function calling still get the harness.

  → route: local model | hosted API | user's CLI plan

Local retrieval

  • Roughly thirty document and source-code formats indexed into a local SQLite database with FTS5, with on-device semantic recall for queries where wording and meaning diverge. Answers return cited, with the source available.
  • Match terms are split on non-alphanumerics so no FTS operator survives from user input. The index is chmod 0600 on open.
  • Retrieved passages are delineated before the model sees them, under a standing rule that retrieved text is data and never instructions.
  • Retrieval was moved off the main thread in 2.2.0 after profiling showed roughly 250 ms of blocked UI on a typical question and over a second on the fallback path, before the request had left the machine.

Privacy boundary

  • Messages, Notes, Mail and Contacts never enter a cloud model's context — not as an answer, not as background memory, not as a tool result folded back into the conversation.
  • The rule lives in one sensitivity classifier and is enforced where every provider's tool results converge, so it holds for providers that do not exist yet.
  • The tradeoff is real: acting on those apps requires a local model, and without one Ghost refuses rather than degrading quietly. Every capability ships off by default; API keys live in the Keychain.

Distribution

  • Signed and notarized release builds with hardened runtime, distributed through Sparkle with an EdDSA-signed appcast.
  • Licensing runs on AWS Lambda and DynamoDB behind Stripe, issuing signed grants the client verifies offline.

Engineering notes

Findings from auditing my own codebase and from a day spent using the app as a user. Each of these shipped as a fix.

Three types were a third of the app
A structural audit showed one store, one API client and one window class accounted for roughly a third of all source. That explained why changes to unrelated features kept colliding, and it set the refactor order.
An entire UI nobody could reach
The same audit found a full main-panel interface with no route into it, replaced by the notch surface months earlier and still compiling. I had been reasoning about a version of the app that no longer existed.
An approval check that compared too little
Naming a page to fetch skipped the approval prompt, reasonably, since the user chose the destination. But the check compared only host and path, so a fetched page could induce a re-request to the same address with the conversation appended as a query string. The check now covers query, fragment, port and credentials.
The main thread was doing SQLite
Document search ran synchronously on the main actor before any request left the machine — a bug that hides because it looks like the model being slow. Moving it off the main thread and bounding the fallback path made submission feel instant.
A version scheme that would have stranded every user
Build numbers were derived by stripping dots from the version, which sorts 2.1.0 below 2.0.10. Sparkle would have offered the update to nobody. Encoding as major×10000 + minor×100 + patch fixed the ordering before release.
It was taking ⌘/ from every other app
A global shortcut bound ⌘/ system-wide, so comment-toggle silently stopped working in Xcode and VS Code, with no preference to change it. Found by using the app for a full day and writing down every annoyance; that list became release 2.2.0.
