Selected work — 01

Ghost

A local-first macOS AI workspace, designed and shipped solo.

Role Sole engineer & designer
Stack Swift · SwiftUI · AppKit · SQLite FTS5 · AWS Lambda + DynamoDB
Status Shipped · v2.2.0 · signed & notarized · Sparkle auto-updates
Live site ↗ Docs & releases ↗ Source is closed; happy to walk through it in an interview.

Ghost started as a question I kept running into as a user: why does an AI assistant make me trust it? A model can claim it wrote the file, moved the event, or read the document, and a thin wrapper will happily print that claim as fact. Ghost is built the other way around. Every capability is a real function the app owns, the app checks permissions and path boundaries before it runs, and what comes back to the model is the actual result — including the failure.

The problem it solves — 01

A capability harness, not a prompt that hopes

Every prompt goes through a local intent classifier first — no network call — which picks one of fourteen intents and, with it, the route: a fully local model in LM Studio or Ollama, a hosted API, or the user's own Claude Code or Codex subscription. Only then is a tool schema assembled, and it is assembled from the permissions that are actually switched on, so a disabled capability is invisible to the model rather than merely discouraged.

Execution re-checks that same policy, because a schema is a suggestion and a gate is not. Tools carry a risk tier; the destructive ones always require confirmation, and the confirmation dialog is shown the real argument JSON rather than the model's description of it, so a persuasive sentence cannot stand in for what will run. Unknown tool names fail closed.

The problem it solves — 02

Retrieval that runs on the machine it searches

Ghost indexes documents and source code across roughly thirty formats into a local SQLite database with FTS5, layered with on-device semantic recall for the cases where wording and meaning diverge. Answers come back cited, with the source in hand, so a claim can be checked instead of believed.

The details that mattered were unglamorous. Match terms are split on non-alphanumerics so no FTS operator survives from user input; the index is chmod 0600 on open; retrieved passages are delineated before the model sees them, under a standing rule that retrieved text is data, never instructions. In 2.2.0 I moved retrieval off the main thread after profiling showed it was costing a quarter of a second of dead UI on an ordinary question, and over a second on the slow path — about twenty times faster now, and the window no longer freezes on Return.

  • SQLite FTS5
  • ~30 formats
  • semantic recall
  • prompt-injection delineation

The problem it solves — 03

One invariant, enforced at a single choke point

Messages, Notes, Mail and Contacts never enter a cloud model's context. Not as an answer, not as background memory, not as a tool result quietly folded back into the conversation. The rule lives in one sensitivity classifier and is enforced where every provider's tool results converge, so it holds for providers I have not written yet.

It has a real cost, and the honest version of this section is the cost: if you want AI to touch your iMessages, you have to point Ghost at a local model, and if you have not, Ghost refuses rather than degrading quietly. I took that trade because a privacy guarantee that bends under convenience is not a guarantee — and because defaults do the actual work, so every capability ships off.

  • on-device only
  • single enforcement point
  • off by default
  • Keychain-held secrets

How I work

What I got wrong, and what I did about it

Shipping the thing is half of it. The other half is being able to read your own code honestly a month later.

Audit

Three types were a third of the app

I ran a structural audit of my own codebase and found that one store, one API client and one window class accounted for roughly a third of all source. Naming that is more useful than defending it: it explains why changes in unrelated features kept colliding, and it set the refactor order.

Dead code

An entire UI nobody could reach

The audit also turned up a full main-panel interface that no longer had a route into it — I had replaced it with the notch surface and left it compiling. Deleting it was the change; the lesson was that I had been reasoning about a version of the app that no longer existed.

Security

An approval check that compared too little

When a user named a page to fetch, Ghost skipped the approval prompt — reasonably, since the user chose the destination. But the check compared only host and path, so a fetched page could talk Ghost into re-requesting the same address with the conversation appended as a query string. The check now covers the whole destination: query, fragment, port and credentials.

Performance

The main thread was doing SQLite

Document search ran synchronously on the main actor before a request had even left the machine. It is the kind of bug that hides because it looks like the model being slow. Profiling put it at ~250 ms typical and over a second on the fallback path; moving it off the main thread and bounding the slow path made Return feel instant.

Distribution

A version scheme that would have stranded everyone

Build numbers were derived by stripping the dots out of the version, which makes 2.1.0 sort below 2.0.10 — Sparkle would have offered the update to nobody. Encoding it as major×10000 + minor×100 + patch fixed the ordering before it shipped.

Users

It was quietly stealing ⌘/ from every app

A global shortcut sheet bound ⌘/ system-wide, which meant comment-toggle stopped working in Xcode and VS Code with no visible cause and no preference to change it. I found it by using my own app for a full day and writing down everything that annoyed me. That list became release 2.2.0.

About

From charts to systems

I spent a year in medical school and, before that, a year as a certified scribe in pediatric orthopedics at UCSF Benioff Children's Hospital Oakland, documenting roughly eight hundred hours of clinical encounters in a high-volume EMR. The job was to capture what actually happened, in real time, precisely enough that someone else could act on it safely — and to notice when the record and the reality had drifted apart.

That turns out to be the same instinct that makes AI systems trustworthy. A model's output is a claim about the world; a harness is the thing that checks it. I left medicine for computer science because I wanted to build the system rather than operate it, and I came in with a documentation habit that has made me a considerably better engineer than my line count suggests: my own architecture audit is the artifact I am proudest of, not the feature list.

I am now a second-year MSCS student in Northeastern's Align program in Silicon Valley, graduating May 2027, and looking for a Summer 2027 internship where I can work on applied AI infrastructure: harnesses, retrieval, evaluation, and getting local models to do real work.
